# Design system: piyush97 profile README

## Overview

**Creative North Star: "The Evidence Ledger"**, inherited from
[PiyushMehta.com](https://github.com/piyush97/PiyushMehta.com). This is the same
product surface as the site, not a separate brand. Its north star, palette, type
roles, and named rules are defined in that repository's `DESIGN.md`; this file
records only how they survive a surface with no CSS.

The defining constraint of this artifact: **GitHub strips CSS from README
markdown and blocks `data:` URIs in images.** There is no stylesheet, no hover
state, no custom property, and no way to set a background colour on an element.
Every decision below is a consequence of that.

## Colors

The full palette is the site's. What changes here is the delivery mechanism.

| Token | Dark | Light | Role |
|---|---|---|---|
| `--ink` | `#171a2f` | `#f6f3ea` | page ground |
| `--surface` | `#222640` | `#fffaf0` | raised panels |
| `--text` | `#f6f7ff` | `#121827` | headings, record labels |
| `--secondary` | `#b4bad8` | `#5a5f70` | supporting copy |
| `--muted` | `#8f96ba` | `#666c7d` | metric sub-labels |
| `--rule` | `#343a5f` | `#ddd3c2` | hairlines |
| `--signal` | `#ffcc68` | `#8d3d1f` | decisions, actions, measured values |

**The Two-Ink Rule** is the site's rule and it is load-bearing here: dark and
light share semantic roles, but each picks its own readable values. Because CSS
cannot do this, every asset in `assets/` carries its own internal
`prefers-color-scheme` block. An asset baked to one theme reads as broken in the
other, because GitHub will not rescue it.

The light `--muted` is `#666c7d`, and neither inherited nor plausible default
value works. Measured against `#f6f3ea`: the site's dark-theme `#8f96ba` is
**2.61:1** and the GitHub-style default `#7c8093` is **3.53:1** — both fail WCAG
AA for 11px text. `#666c7d` measures 4.72:1 on paper, 5.24:1 on white, and
5.04:1 on paper-surface.

## Typography

Muli carries the voice. Source Code Pro is reserved for measured artifacts:
record labels, metric values, and their sub-labels. That is the site's *Code
Means Code* rule, and on a surface with no other typographic device it does more
work than usual.

GitHub sets the reading face itself, so type here is a fixed ladder rather than a
scale the artifact controls: `h1` for the name, `h2` for sections, body for
prose. Hierarchy is built from weight and section order, not from size the
README can tune.

## Layout and the responsive problem

**GitHub does not reflow.** A table that reads well at 960px crushes at 390px,
because each column simply gets narrower. This is not a styling bug that a media
query could fix; there are no media queries. Two consequences shaped the build:

- **No table holds prose.** An earlier revision used a three-column
  `Constraint / Decision / Outcome` table and a three-column project table. At
  390px both collapsed into vertical ribbons of two- and three-character lines.
  Both are now stacked blocks that read at any width. The record's *sequence* is
  preserved; only the side-by-side arrangement was given up.
- **Wide assets need a narrow twin.** The four-up outcome rail is 880px
  intrinsic, which scales to ~0.44 at 390px and drops its 11px labels under 5px.
  `assets/metrics-compact.svg` is a 2x2 variant at 460px, swapped in by a
  `<picture>` `max-width` media query. GitHub supports `<picture>` and emits
  `<themed-picture>`, which is also how the contribution snake is served per
  colour scheme.

## Assets

All colour arrives as committed SVG referenced from `raw.githubusercontent.com`,
generated by `scripts/generate-readme-assets.mjs`. Run it after any token change;
the committed files are byte-identical to a fresh run.

| Asset | Job |
|---|---|
| `mark.svg` | brand monogram, 64x64 |
| `record-01/02/03.svg` | the record's numbered mono labels, uniform 200x20 |
| `metrics.svg` | four-up outcome rail, 880x104 |
| `metrics-compact.svg` | 2x2 outcome rail for narrow viewports, 460x208 |

**Record markers share one canvas width.** They also share one
`font-size: 13px; font-weight: 700; letter-spacing: 0.12em` rule, so they must
render at one scale. An earlier version sized each canvas to its own label length
and the README then forced all three to `width="180"`, which stretched `OUTCOME`
by 1.146x and squeezed `CONSTRAINT` by 0.947x. Fixed canvas, and no forced
`width`/`height` in the README.

**A label is stated once.** The marker asset carries `01 CONSTRAINT`; the prose
begins at the verb. Repeating the word in a bold lead-in said it twice, in two
typefaces, about 90px apart, three times over.

## Named rules

**The Ledger Rule.** Amber marks decisions, actions, and measured values. It
appears on the three record numbers, the four metric values, the monogram, and
the primary action. It does not appear on section headings or body copy.

**The Weight Before Color Rule.** The site's rule, and here it is the only
hierarchy available, since the artifact cannot set type size.

**The Code Means Code Rule.** Mono marks the record and the metrics. It is never
a costume for "technical."

**The Two-Ink Rule.** As above. Every asset ships both schemes.

## Known platform breaches

These are GitHub's, not choices, and are recorded rather than papered over:

- **Code spans** (`@astrojs/vercel`, `output: 'server'`) render in GitHub's chip
  grey inside the proof paragraph. Neither contract ink nor signal is available
  for inline code, and the chips sit in the page's most credibility-bearing
  sentence.
- **Links** render in GitHub's link blue, not amber.
- **The action badges** are `shields.io`, hardcoded to `#171a2f`, so they stay
  navy in both schemes while the monogram above them swaps to cream. This is the
  one place the masthead's grounds disagree. The alternative was no action row,
  which is worse on a Persuade surface.
- **`<hr>` is heavier than the 1px hairline** the contract specifies, and `h1`/`h2`
  underlines are GitHub's `--borderColor`. Three rule weights exist on the page.
  Every top-level section receives the same `---` so at least the rhythm is
  uniform.

## Automation

Three workflows write into this README. Their marker pairs are structural, not
decorative, and must survive any edit:

| Markers | Workflow | Cadence |
|---|---|---|
| `<!-- BLOG-POST-LIST:START/END -->` | `gautamkrishnar/blog-post-workflow` | nightly |
| `<!--START_SECTION:activity-->` | `jamesgeorge007/github-activity-readme` | every 30 min |
| `charts/github-snake*.svg` | `Platane/snk` | nightly, files only |

None trigger on push. A redesign that empties those regions ships visibly empty
sections until the next scheduled run, so the populated contents are ported
across by hand rather than replaced with placeholders.

`waka-time.yml` was removed with the WakaTime block it maintained. Leaving it
would have re-inserted a 60-line auto-generated block on the next nightly run.
